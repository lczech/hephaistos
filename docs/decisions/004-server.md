# 004: Server

Status: accepted (2026-10-10)

## Context

GUIs reach a Machine only through its Server ([002](002-technology-stack.md)): the Desktop on the same Machine, later another Machine's GUI and the phone. The Server's address, its authentication and the shape of its API are what they all build on, so they are costly to change.

## Decision

- **Address:** the Server is a part of the Daemon (`server.enabled`, on by default) and listens on `127.0.0.1` only, at `server.port` (8264). Other Machines and the phone reach it through the network, outside our code: `ssh -L 8264:127.0.0.1:8264 <machine>`, or `tailscale serve`. A port already in use fails only the Server, which is retried like any crashed part; `server.port` per host fixes it. A client learns another Machine's port by asking over SSH (`daemon status --json`).
- **Someone else's port:** any user of a Machine can listen on a free port of 127.0.0.1, also 8264 before our Daemon starts, and so receive the token from clients. Our clients send it only to a port that Linux lists as the user's (`/proc/net/tcp`): `daemon token --url` refuses otherwise, and a Server that finds its port taken says by whom, and to renew the token. Our links name `127.0.0.1`, as `localhost` may first try IPv6, where someone else could listen. curl by hand, forwards set up by hand and the phone don't check; `browse` does, but hands the link to the browser on its command line, which other users can read. On personal Machines only the user has an account; on a shared one, `server.port = 0` takes a free port at each start, reported once listening, so nobody can take it first. A Unix socket would also have prevented it, but makes typing commands and forwards harder, and browsers can't use one.
- **Token:** every API request needs this Machine's token: 32 random bytes as URL-safe base64, in `server.token` in the data directory, mode 0600, created on first use. localhost is shared by other users and services, websites in the browser can send requests to it, and Tailscale opens it to the tailnet; the token keeps them all out. Whoever can log in as the user can read it, so SSH is the root of trust: a client fetches it over SSH (`hephaistos daemon token`) when it connects, never stores another Machine's token, and Sync never carries it. `daemon token --renew` replaces it; the Server reads it again when the file changes.
- **Sending it:** only as `Authorization: Bearer <token>`. Not in a cookie: cookies aren't kept apart by port, so a browser would also send it to every other service on localhost, e.g. a Jupyter or a forwarded one. Not in a query: URLs end up in logs. A browser gets it once from a link's fragment, `http://127.0.0.1:8264/#token=<token>` (`daemon token --url`), which it never sends; the GUI keeps it in the browser's local storage for that origin and takes it out of the address bar, also from a link opened in the page later (the Desktop's, after a renewal), and forgets it on a 401, unless a newer one came meanwhile. A live connection, a WebSocket, to which a browser can't add headers, sends it as its first message. Requests must name `localhost` or `127.0.0.1` as their host, against DNS rebinding. Tokens are compared in constant time; refusals are logged as warnings, never with the token.
- **API:** the API returns what the CLI's `--json` prints, built by the same Core functions (`core/serialize.py`, TypedDicts), so they can't drift apart; a test requires an endpoint for every command with `--json`. Entities are addressed by full ID, as names change; other entities are referred to as `{id, name}`. Lists come whole, except Events, which page back with `before=<id>`, the log, back with `before=<position>`, and a table's rows, with `offset`. Paging back, lists by time come newest first, as the CLI's with `--reverse`. `POST /api/observe` has the Watcher pass ([003](003-core.md)) and answers 204 once it ended, 503 if it failed; what changed, the other endpoints show. Four endpoints have no command: a Checkout's changes (`/api/changes`), a file's change with git's patch (`/api/diff`), its two versions, to show more around the changes (`/api/diff/files`), and its commits (`/api/history`, paged on from where a page ended, following a file's renames: where a file's history ends, its oldest commit is checked for having renamed it); from git each time they're asked, never stored, as `git status`, `git diff` and `git log` already show them in a terminal; `commit=` asks for what a commit changed against its first parent, with whether a branch, tag or HEAD still leads to it and, if not, what amends of it led to, by the Events; bare Clones answer what compares only commits; patches and versions only up to `gui.diff.max_bytes`; git runs read-only, with no external diff tools, and the states compared are checked with `rev-parse --verify --end-of-options`. The settings are those the Daemon finds, with what it applies; JSON with something unusual to say, e.g. an outdated schema, says it in `warnings` next to the data. Errors are `{"error": "<the CLI's message>"}` with 400, 401 or 404; unexpected ones are 500, their traceback only in the log. The OpenAPI schema at `/openapi.json` describes the endpoints; this document doesn't list them. FastAPI's `/docs` page is off: it runs scripts from a CDN, which would see the token.
- **Live:** `/api/live` is a WebSocket over which the Server hints at what changed (`{"hints": ["data", "daemon", "log"]}`), never with the data: GUIs ask the endpoints again. While any connection is open, one loop looks every second, and at once after `POST /api/observe`: at the database's `data_version`, the Daemon's status but for its counts (which asking again changes), and the log's size. A heartbeat every 10 s lets GUIs notice a Server that hangs; with it, the loop checks that the clock didn't move without a `data` hint, logging and hinting a change it missed. A client that falls behind is closed rather than sent fewer hints, and renewing the token closes all. Browsers let any page open WebSockets to localhost, so a connection with an `Origin` must come from the Server's own page. Each endpoint names what keeps it current (`KEPT_CURRENT`: a hint, the GUI gaining focus, or reconnecting), which a test holds to the endpoints; the messages are in the OpenAPI schema.
- **Types for the GUI:** the TypedDicts become the API's OpenAPI schema, from which the GUI generates its TypeScript types.
- **The GUI's files:** the Server serves the GUI's build, from `gui/web/dist/` in the checkout it runs from: `/` and `/assets/…`, without the token, as they hold no data and a browser can't send a header when opening a link. Everything else, the API above all, needs the token; the Host check covers all. As the page keeps the token, every response forbids it anything but our own files and connections to this Server (Content-Security-Policy: no inline or foreign scripts, no framing; inline styles, which the diff renderer sets, can send nothing out, as nothing else may load or connect), with `Referrer-Policy: no-referrer` and `nosniff`; so the GUI uses no CDNs, web fonts or analytics. `/assets/` is named by content and cached for good, the page is checked each time, so a rebuild needs no Daemon restart. Without a build, `/` names the build command.
- **Version:** `GET /api/info` gives the running version and `api: {major, minor}` (`API_VERSION` in `core/serialize.py`). A change that breaks clients bumps major; one that only adds bumps minor. Until 1.0, while nothing depends on it yet, the API may change in any way and every change bumps minor. A client requires the same major, and checks minor before using what it added (before 1.0: the same version). A test holds the schema to a recorded snapshot and requires the right bump. The GUI knows the version it was built for: it stops at another major, and names `hephaistos daemon restart` for a Daemon with an older minor or, before 1.0, another version. URLs carry no version, and no old versions are served while things are in flux.
- **Running:** in the Daemon's process, as an asyncio task (uvicorn), its endpoints in threads with read sessions. FastAPI and uvicorn are regular dependencies, imported only when the Server starts; a test keeps them out of the CLI's start. Each request is logged at DEBUG, its query decoded and any `token` in it hidden.

## Rejected

- **Listening on other interfaces, TLS, accounts:** SSH and Tailscale already connect and encrypt; there is one user.
- **Versions in URLs (`/api/v1/`):** they only pay off when serving old versions side by side.
- **FastAPI as an optional extra:** two ways to install for about 10 MB saved.
