# 005: GUI

Status: accepted (2026-10-13)

## Context

The GUI ([002](002-technology-stack.md)) is one React app for the Desktop, browsers and later the phone. It shows many kinds of content side by side: the Daemon, Events, later Repositories, Terminals, Agents and files. How content is named, placed and kept is costly to change once there are many Views. How the Server serves the GUI, the token and the Content-Security-Policy are in [004](004-server.md).

## Decision

- **Terms:** a View shows something, by its kind and parameters; a Panel is a tab showing one View; Groups hold Panels as tabs, side by side or stacked; the Layout arranges the Groups ([glossary](../glossary.md)). dockview (`dockview-react`) provides Panels and Groups.
- **Views know nothing of dockview:** `gui/web/src/views/` has a folder per kind, named with its icon in `views/kinds.ts` and its component in `views/index.ts`; a View gets its parameters as props, with ways to change them and its tab's title. Only `layout/` uses dockview, so that a phone shell can show the same Views as pages, and dockview's frequent major versions stay in one place. Views open other Views through `useOpenView` (`views/opening.ts`), which `layout/` provides with our `openView`, never dockview's API: from a Panel's Group from within it, elsewhere from the active Group (`layout/ViewOpener.tsx`), e.g. from the status bar, whose Daemon icon, coloured by the Daemon's health, opens the Daemon View.
- **Addresses:** a View's address is its kind and parameters as text, sorted: `events?repository=…`; a parameter with several values repeats, `kind=clone&kind=worktree`. A Panel keeps its View's kind and parameters in dockview's Panel parameters, which a View can change, e.g. by filtering, and are saved with the Layout; its ID is random, as a Panel's View can change. Opening a View that a Panel shows (the same address) focuses that Panel; two Panels may show the same View. The phone shell will use addresses as page URLs, after `#`.
- **Opening:** "+" in each Group's tab bar lists the kinds; an empty Group lists the suggested ones; a View opens others in its own Group or beside it, e.g. by a `ViewLink`, a button with the kind's icon (and its name, where there's room), greyed out where it would show nothing that needs a look, e.g. a Checkout without changes. Beside is the Group touching it on the right, else below, left or above; of several on that side, the topmost (right, left) or leftmost (below, above), by their sizes on screen (`layout/beside.ts`); a Group alone is split, to the right. A View may open as a preview, e.g. one Repository's Events: one per Group, which the next preview replaces (the Panel stays, its View changes), its title in italics; it is kept, an ordinary Panel, once its tab or link is double-clicked, it is changed (filtered, sorted, …), or it is dragged to another Group. Previews are a Panel parameter beside its View's, so the Layout keeps them. Later also from sidebars (dockview's edge groups) and a command palette.
- **Saving:** the Layout is kept per browser, in localStorage, with a format number. A Panel whose kind no longer exists says so; a View that fails, e.g. on parameters it no longer understands, shows its error in its Panel only; a Layout that can't be restored gives the default one. No migrations.
- **Keys:** Ctrl+W closes the active Panel; only the Desktop passes it to the page, as browsers close their tab.
- **Empty Groups:** dockview closes a Group with its last Panel, except the last Group, which shows the suggested Views. It has no public option to keep them; asked upstream.
- **Later, Workspaces:** one window switches between Workspaces, ordered by hand (lists of Repositories are ordered by name or activity instead), e.g. one per Repository, each with its own Panels in a named Layout that Workspaces share (at first, all the same one). Each Workspace keeps its own dockview, all of them mounted and the hidden ones not asking again until shown; a shared Layout that changed is applied when its Workspace is shown. This needs Groups that stay when empty.
- **Live updates:** the GUI asks the Server again only when its live connection hints at a change, never on a timer (`api/live.ts`, which maps each hint to the queries it covers, by the names in `KEYS`); connecting asks again for everything, and gaining focus asks for a pass and for what changes by hand: the settings, and Checkouts' changes, as editing a file changes no State. Answers stay current until then (`staleTime: Infinity`). It reconnects after 1, 2, 4 … 30 s, and at once on focus; 25 s without a heartbeat count as lost. The status bar says live or since when disconnected, the Daemon's icon turns lost, and the Daemon View says what to check.
- **Lists:** TanStack Table (`@tanstack/react-table`, headless) holds a list's columns and their state; Views render them as CSS grids of their own markup (`components/table/`). A row opens its details by the button in its first cell, or by a click anywhere else on it but on its cells' own buttons and links, and not one selecting text. Tooltips are native (`title`): a cell's own where it adds something (a full time, a status spelled out), else its whole text while cut off; a header's says what the column shows, if its label doesn't. Columns may sort (TanStack's sorting, off unless a column turns it on; the order is a View parameter, `sort`), rows may hold rows (`getSubRows`, `data-depth`), which rows that fold open instead of details (the Changes View's groups, directories with changes, and new folders, whose files are asked for once opened), rows that open another View instead (a changed file its Diff, beside, as a preview, kept by a double click), and rows that show all they have open nothing (a note), and a filter may be linked: set only from outside, e.g. by a link, and offered only while set. Narrow Panels show a row in two lines: its square and icons beside what it is, its details below, one after the other rather than in columns, which would only line up by chance, and times at the end, where they line up. Column widths can be dragged; they are kept per kind of View in the browser (`hephaistos.columns.<kind>`), shared by all its Panels, and not part of addresses. Widths reach the grid as CSS variables. A column's header filters by it: one choice for a point on a scale (a priority or higher, since a time), any of several for a set (kinds, Repositories), none meaning all. Filters are the View's parameters, by the names of the API's, which filters like the CLI; so they are saved with the Layout, and the tab's title names them.
- **Diffs:** the Diff View shows git's patch of one file (`diff?clone=…&from=…&to=…&path=…`), rendered by `@pierre/diffs`, pinned, imported only by `components/diff/` and loaded once a diff shows, so another renderer could replace it; Shiki highlights it with the themes `gui.code_theme_light` and `gui.code_theme_dark` name, on the page's background; its header is ours, as the file's row in Changes shows it, and stays in view below the View's bar. Side by side (inline in narrow Panels), wrapped, or the whole file (turned off, the diff starts anew, as the renderer can't fold lines shown again): chosen for all Diffs, kept per browser (`hephaistos.diff`). Large diffs (`gui.diff.large_lines`) wait to be shown; an empty one offers where the file's changes are now, in the same Panel.
- **Later, other Machines' logs:** logs aren't synced, so another Machine's log comes from that Machine's Server, once the GUI reaches other Servers (decided with remote Machines). The Log View takes the Machine as a parameter, `log?machine=…`, this Machine without one, chosen above the list rather than filtered: a log is one Machine's at a time.
- **Look:** CSS modules and the custom properties of `theme.css`, with VS Code's greys; dockview's light theme for sizes, with its colours from `theme.css` (`layout/dock.css`), so it follows the system's light or dark. Monochrome icons from Lucide (`lucide-react`), mapped in `icons.tsx` by action and entity type, a dot for anything else. Icons beside text sit a little above the middle of its capitals, by two values in `theme.css` (`--icon-drop` inline, `--icon-lift` when centred), not by nudges per icon. Brand logos only for links to forges (`forges.ts`), from Simple Icons (`simple-icons`, CC0, imported one by one). Each kind of View has one, shown before its tab's title (`layout/ViewTab.tsx`, around dockview's own tab) and in the lists of kinds.

## Rejected

- A Layout per Repository: rearranging one wouldn't rearrange the others, as with separate VS Code windows.
- Swapping Panels when switching Workspaces: it would recreate every View, losing Terminals' state and scroll positions.
- Keeping empty Groups with a placeholder Panel, or through dockview's internals: workarounds that break when dockview changes.
- Layouts in the Registry: an arrangement fits a screen, not every device.
